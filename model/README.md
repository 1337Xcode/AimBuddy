# AimBuddy model store

The detectors AimBuddy runs are published from this folder. The app lists them, installs the one the player picks and says when a newer version exists. There is no server behind it: the store is a static `index.json` and the model files, served straight from this repository.

A model here is an object detector that finds people in a game picture. AimBuddy turns its boxes into outlines on the screen and, when the player switches the assist on, into the targets the aim assist works with.

## How it works

- `index.json` is generated by `model/index.py` from the model folders. For each model it lists the title, description, author and version, and for each file its path, size and SHA-256. It is never edited by hand.
- The app reads the index with one request and keeps the last copy, so the store still opens without a connection. It checks that the index is well formed, and that every path stays inside the store, before it downloads anything.
- Every downloaded file must have exactly the size and SHA-256 the index gives for it. A model is moved into place only when all of its files are complete, and the old copy is kept until then, so a failed or cut-short download never harms a model that works.
- The default model, `aimbuddy-general`, is also copied into the APK when the app is built (`app/bundled-model.gradle`). This folder is its one source, and a first run needs no connection. A downloaded copy of it replaces the built-in one only if its `version` is at least as new.
- `.github/workflows/models.yml` runs `python model/index.py --check` for every change under `model/`, so the index cannot drift from the files. Files are served byte for byte (`model/** -text` in `.gitattributes`), so the hashes do not depend on line-ending conversion.
- `model.json` tells the app how to read a network's output, so any NCNN export of a YOLO-style detector works without a change to the app.

## Add a model

1. Make a folder named for the model's id: lowercase letters, digits and dashes, 2 to 40 characters, not ending in a dash.
2. Put these files in it:

   | File | What it is |
   | --- | --- |
   | `model.param` | The NCNN network graph. |
   | `model.bin` | The NCNN weights. |
   | `model.json` | What the model is and how to read its output (below). |
   | `icon.png` | Optional. A square PNG of at most 128 KB, shown in the store. |

3. Run `python model/index.py` to rebuild `index.json`, and commit it with the folder.
4. Open a pull request. A check runs `python model/index.py --check` and fails if `index.json` is out of date.

Files are served exactly as committed, so do not change their line endings.

## model.json

```json
{
  "title": "AimBuddy General",
  "description": "Finds people in most 3D shooters without training for your game.",
  "author": "AimBuddy",
  "version": 1,
  "roles": ["body"],
  "inputSize": 256
}
```

- `title` (at most 40 characters), `description` (at most 160) and `author` (at most 40) are shown in the store.
- `version` is a whole number from 1. Raise it whenever the model's files change: the app offers an update to everyone who has an older version.
- `roles` lists what each class of the network is, in class order:
  - `body`: a person to find. The box is outlined and tracked.
  - `head`: that person's head, for a model that detects heads as a class of their own. The assist prefers it as the aim point.
  - `ignore`: detected but never outlined or aimed at, for example a teammate or the player's own character.

  Classes that are not listed are ignored. With no `roles`, one class means `body` and two classes mean `body` then `head`.
- `inputSize` is the network's input size in pixels. Leave it out to have the app work it out.
- `endToEnd` is `true` for an export that already removes duplicate boxes (output of N rows of six numbers).

The app saves this file next to the model and reads `roles`, `inputSize` and `endToEnd` from it.
